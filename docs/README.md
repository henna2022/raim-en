# 하위 모델 위임 지시서 (P0 하드닝)

각 파일을 **별도 세션에 하나씩** 복붙해서 위임한다. 순서 고정:

1. `P0-1-spam-ratelimit.md` — 공개 폼 스팸 방지 + rate limit
2. `P0-2-csrf.md` — CSRF (더블 서브밋 쿠키) ※ P0-1 머지 후
3. `P0-3-admin-auth-session.md` — 로그인 잠금 + SQLite 세션 스토어 ※ P0-2 머지 후
4. `P0-4-test-suite.md` — 자동화 테스트 ※ P0-1~3 머지 후

## 위임 시 세션 시작 프롬프트 (복붙용)

> ~/Desktop/raim-en 프로젝트에서 docs/P0-N-....md 지시서대로만 작업해줘.
> 지시서의 [컨텍스트 고정]과 [금지사항]은 절대 위반하지 말고,
> 판단이 필요한 상황이 생기면 작업을 멈추고 질문해.
> 끝나면 [완료 기준]의 각 항목을 실행한 증거(명령어+출력)를 붙여서 보고해.

## 검수 체크리스트 (사람 또는 상위 모델)

- [ ] 완료 기준 증거가 실제 출력인가 (요약문이 아니라)
- [ ] `git diff` 범위가 지시서에 명시된 파일들뿐인가
- [ ] 새 의존성이 package.json에 추가되지 않았는가
- [ ] e2e 1회 완주(예약→승인→취소)가 여전히 통과하는가
- [ ] 각 단계 머지 후 다음 지시서로

모든 P0 완료 후: 상위 모델(Fable 5)로 전체 diff 적대적 리뷰 → 운영 루프(신규신청 노티/취소 시 yeyak 해제 큐/SLA 표시)와 개인정보 자동 삭제 구현으로 진행.
